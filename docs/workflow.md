# Debug work within the shared project stages

[Repository home](../README.md) · [Orientation](orientation.md) · [Implementation details](implementation-plan.md)

The [central stage gates](https://github.com/motion-tennis/documentation/blob/main/docs/project-stages.md) define one project sequence. The [central status](https://github.com/motion-tennis/documentation/blob/main/docs/project-status.md) records the active stage, evidence and outstanding gates. This page maps debug responsibilities into that sequence; it neither declares a stage passed nor creates another mutable progress register. Use the [central contribution workflow and task/handoff template](https://github.com/motion-tennis/documentation/blob/main/docs/contribution-workflow.md) for each bounded human or AI task.

A repository slice completing its column does not complete the shared gate. Prerequisites and cross-repository evidence remain governed by the central stage definition. Existing offline tools are a verified starting asset, not proof that S1 or a later stage has passed.

## Task and handoff discipline

Resolve central status, pin the contract/reference revisions and name a bounded stage task before implementation. Describe inputs, expected outputs, acceptance cases and deliberate exclusions using the central template. Read existing tests before adding checks; a test that merely accepts an unknown stage name does not prove marker, clock or match semantics.

Implement only the authorized slice and required routine fixes. Run the relevant real [checks](orientation.md#available-checks), review the diff, and report what changed, exact results, evidence limits and remaining dependencies. Update actual coverage documentation when implementation warrants it; do not mark a whole stage complete from local success or automatically start its successor.

A direct human instruction naming a bounded future-stage slice can authorize an exception. Record that instruction, stage, exact scope, unmet gates and handoff limitations; the global stage remains unchanged and neighboring work is not implied. Routine fixes/checks already within the authorized slice do not need another approval. If central files are unavailable, a verified pinned status/task record is usable; absent reliable evidence, resolve the missing stage context before dependent implementation.

## Evidence rules across every stage

Retain raw timestamps, sessions and identities. Use Pi-issued maps and their applicability/uncertainty rather than a new viewer fit; preserve local lanes when mapping evidence is missing. Separate actual runtime-map usage from permitted display-only assignments. Same-controller RTT remains measurable without cross-device mapping.

Keep every started sample and its terminal/failure accounting; markers add diagnostic links without changing 200 Hz traffic, queue priority or expiry. Do not convert a missing trace stage into a successful transaction or a technical error into a tennis point. Synthetic fixtures, live application records, packet captures and electrical/physical measurements remain distinct evidence populations.

Use bounded asynchronous producers, collector queues and storage. Tests at S2 and later must demonstrate that a stalled or absent observer cannot block gameplay. Shared contract changes require the corresponding central/component documentation and fixtures within the authorized task; this repository cannot silently redefine fields, clock ownership or match authority.
